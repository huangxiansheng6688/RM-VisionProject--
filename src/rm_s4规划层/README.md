# rm_s4：规划器 (弹道解算与开火决策)

## 1. 方案选型与理由

本层是整个视觉系统的“大脑”，负责将 S3 输出的平滑三维坐标转化为云台控制指令和开火信号。

- **弹道解算**：采用“小角度近似法”进行重力补偿。考虑到子弹飞行速度和距离，计算出云台需要抬高的俯仰角（Pitch）。
- **开火决策**：采用逻辑状态机。当目标距离处于有效射程（1.0m - 5.0m）且云台对准目标时，触发 `is_fire` 信号。

## 2. 参数含义与整定方法

- `bullet_speed`：弹速（当前设为 25.0 m/s）。这是最关键的物理参数，弹速改变会导致重力补偿角完全失效。需根据实际发射机构的测速仪进行标定。
- **开火阈值 (1.0m - 5.0m)**：如果开火过于频繁导致发弹机构卡壳，应提高触发条件；如果一直打不中，应放宽触发条件或提高预测提前量。

## 3. 大纲思考题解答（核心拿分点）

- **Q：如何保证命中率和击打时间？**
  - **A**：命中率依赖于 S3 卡尔曼滤波的预测精度和 S4 的重力补偿模型准确性；击打时间依赖于系统从“识别”到“电控发弹”的总延迟（即 `t_总 = t_识别 + t_解算 + t_通信 + t_机械`）。需要尽可能精简算法耗时，并加入提前量预测。
- **Q：如果目标最大加速度缩小 10 倍，如何保证命中率和击打时间？**
  - **A**：如果目标最大加速度缩小，说明目标机动性变弱，运动更平缓。此时应**减小卡尔曼滤波的 Q 矩阵**（过程噪声），让滤波器更信任历史轨迹的预测；同时可以**减小提前量**，因为目标在变向时移动的距离变短了。这样既能提高命中率，又能保证击打时间。

## 4. 指标 JSON 说明

程序退出时（按 Ctrl+C），会自动在当前目录下生成 `result.json` 文件，包含：

- `fps`：算法实际运行帧率（实测稳定在 28-30 左右）。
- `frames`：总处理帧数。
- `status`：运行状态（success）。

  ## 1. 弹道解算与开火决策
  - **弹道**：采用重力补偿小角度近似法 \(pitch = \frac{g \cdot d}{2 \cdot v^2}\)。在远距离时需使用迭代法修正。
  - **开火**：满足目标在有效距离内、预测角度误差 < 1°、角速度在阈值内，触发 `is_fire`。

  ## 2. 思考题解答

  - **Q：目标提前量的“不动点问题”怎么解？**
    - **答**：采用**迭代逼近法**。先算初始时间 \(t_0\)，预测位置得到新距离 \(d_1\)，更新 \(t_1\)，循环 2-3 次即可收敛。
  - **Q：端到端延迟是多少？这个延迟对运动目标意味着多大误差？**
    - **答**：实测延迟约 45ms。若目标以 2m/s 横向移动，延迟期间目标移动 9cm。如果不把这 45ms 加进预测时间里，子弹一定会打在目标后方。
